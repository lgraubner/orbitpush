# Domain commands edit orbitpush.json, which stays the source of truth

Domains are set up with `orbitpush domains add|remove|list` instead of the first-run questions of `deploy`, but the commands write `domain` and `aliases` in `orbitpush.json` and `deploy` keeps reconciling the pull zone against them. Taking domains out of the config entirely would have kept `deploy` free of hostnames, but a hostname added in the bunny.net dashboard would then serve the site without a redirect and nothing would notice, and the primary domain would have to be inferred from the alias rules. bunny.net only issues a certificate when it is asked after DNS points to it, so `domains add` waits for DNS and is run again to finish, instead of a separate check command, and `--primary` switches the primary domain only once the new one is connected. Because a hand edit can make an unconnected hostname the primary domain, `deploy` holds back alias redirects while the primary domain is not connected rather than redirect working hostnames to one without HTTPS. There is one primary domain per site; several would need a list in `domain` and a target per alias. Revisit if bunny.net issues certificates on its own once DNS points to it, or if a site needs more than one primary domain.
